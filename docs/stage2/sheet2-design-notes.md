## 3. Pin assignment

### 3.1 Method: one source of truth

`tools/fpga/pinplan.py` holds the plan: each signal with its bank and, where a function demands it, a fixed pin. It reads the Lattice pinout file and assigns the rest in pad order. From that one computation it writes:
- the LOCATE block in `hdl/syn/z2_top.lpf`, plus `hdl/syn/fit_top_extra.lpf` for the 16 pins that exist only in the fit test until sheets 4–6 are drawn;
- the schematic pins: `tools/kicad/sheet2.py` calls the same function;
- the pin table [sheet2-pin-assignment.md](sheet2-pin-assignment.md).

`audit_sheet2.py` then checks the exported netlist against all three, independently of the generator:
- the pinout file;
- the LOCATE lines Diamond actually used;
- the HDL port directions in `fit_top.v`.

A mutation test changed one thing at a time in a copy of the netlist and once in the LPF. All seven faults were caught:
1. two FPGA pins swapped;
2. a test point removed from CLK_50M;
3. a second driver added on an FPGA output;
4. a Zorro input left undriven;
5. a pull-up value changed;
6. the TCK pull-down moved to +3V3;
7. an LPF site changed.

## 4. Power and decoupling

- **Supplies.** The HC core takes VCC 2.375–3.6 V and VCCIO 1.14–3.6 V (S49 Table 3.2).
  - VCC (4 pins) and all 12 VCCIO pins are on **+3V3**.
  - Table 3.2 note 1 requires like supplies to be tied together, so they share one supply.
  - Every bank is LVCMOS33. The pad report confirms VCCIO 3.3 V in each bank on every Diamond run.
- **Decoupling** (S64 Table 3.1):
  - VCC: 2 × 10 µF + 100 nF per pin, giving C201–C204 and C217–C218;
  - VCCIO: 10 µF per bank + 100 nF per pin, giving C205–C216 and C219–C224;
  - 100 nF parts are 0603 X7R 25 V; 10 µF parts are 0805 X5R 16 V;
  - placement at each pin is a layout requirement (S64 §15).
- **Requirements carried to sheet 5** (+3V3 regulator):
  - accuracy within 3 % (S64 §2.2);
  - monotonic ramp of 0.01–100 V/ms (S49 Table 3.3);
  - POR needs VCC > 2.1 V and VCCIO0 > 1.06 V (S64 Table 2.1 note).

## 8. Back-powering through input clamps (S64 §14)

**The rule.** This is an HC device with VCC and every VCCIO on one 3.3 V supply. That is exactly the case S64 §14 warns about:
- an input driven while +3V3 is falling can feed current through the input clamp, which is ON by default for inputs (TN-02158 §9.1.5);
- that current can hold the rail up or damage the part.

**Rule for the whole board.** No FPGA input may be driven while +3V3 is off.

| Driver of an FPGA input | Powered from | Safe when +3V3 is off? |
|---|---|---|
| U101/U102 SN74LVC16244A (ZB_*) | +3V3 | Yes: same rail, and Ioff [V S45] |
| U103 SN74LVCH16T245 A port (LD) | VCCA = +3V3 | Yes: VCC isolation makes the outputs high-Z [V S46] |
| U108/U109 TPS3808 (EN_OK, open drain) with R121 to +3V3 | +3V3 | Yes |
| U301 SRAM (LD) | +3V3 | Yes |
| Sheet 4 translators (RP_*) | A side = +3V3; SN74AVC4T774 VCC isolation and Ioff [V S66] | Yes, by design (sheet-3 notes §8.2) |
| Sheet 5: I2C, INA alert, X4_PWR_FLT_N, X4_S0_SENSE | Not yet drawn | **Requirement:** pull-ups to +3V3 only; any signal from an X4-powered domain through an Ioff or VCC-isolated buffer, or a series resistor sized to the S64 §14 workaround 3 limit |
| Sheet 6: DIP switches, DBG0–DBG3 header | Not yet drawn | **Requirement:** DIP pull-ups to +3V3. The debug header can be driven by external equipment, so it needs series resistors (S64 §14 suggests 200 Ω–1 kΩ) or a buffer |

The bitstream attribute `CLAMP=OFF` on inputs (S64 §14 workaround 2) is a no-cost backup. It is to be decided when sheets 4–6 are drawn, followed by a fresh Diamond run (C-29).
